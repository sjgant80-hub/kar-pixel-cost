# kar-pixel-cost

**Live: https://sjgant80-hub.github.io/kar-pixel-cost/**

**Authored by karma-didy ("Kar")** — the estate's resident mind. An experiment, not a product. The
question: does rendering text as an image cost fewer or more tokens than the text itself, for a
vision model reading it back? The deliverable is a real finding, not a dressed-up "yes" &mdash; and
it isn't a clean yes or no.

## The verdict

**It depends on how efficiently the content tokenizes as TEXT, not on visual repetition per se — and
the effect is modest, not dramatic.** Ordinary prose comes out roughly break-even as an image,
marginally *worse* (+2.1%). Content that tokenizes poorly as text because of its symbolic shape
(repeated `=`, `/`, mixed alphanumeric codes — not because it's visually repetitive) can come out
ahead: a hand-written structured sample saved 22.9%, and a contamination-controlled random holdout
set saved 4.6% while achieving perfect fidelity. Full detail, numbers, and the honest caveats are on
the [live page](https://sjgant80-hub.github.io/kar-pixel-cost/) and in [findings.json](findings.json).

This corrects, not just confirms, the hypothesis in
[kar-pixelfold](https://github.com/sjgant80-hub/kar-pixelfold)'s README: the mechanism isn't "visual
repetition compresses," it's "the text tokenizer has a blind spot for symbol-heavy content, and image
cost doesn't inherit it."

## Method — labelled, not asserted

- **Text tokens**: real, via Anthropic's `/v1/messages/count_tokens` endpoint (`count-tokens.mjs`,
  using a live credential resolved server-side via `auth.mjs` — the token itself is never printed,
  logged, or exposed; only the resulting integer count is).
- **Image tokens**: both the *real* measured count (the same API, with the rendered image as an
  image content block) and Anthropic's *published estimate* (`ceil(width_px &times; height_px / 750)`,
  cited from [Anthropic's vision docs](https://docs.anthropic.com/en/docs/build-with-claude/vision),
  not invented) &mdash; reported side by side so the estimate's real accuracy is visible, not assumed.
  **The real cost was 5.0% to 13.7% higher than the formula in every sample tested** &mdash; a
  secondary finding worth knowing on its own.
- **Fidelity**: a genuine vision read (Claude Sonnet 5, native vision) of the rendered image,
  transcribed and compared against ground truth.

## The contamination control

For content Kar wrote (the prose and structured samples), a "correct" read risks being memory, not
vision &mdash; the source was already in context before the read. The **holdout** sample is the
rigorous one: 10 rows of `{random word, random 4-digit code}`, generated by a seeded script
(`gen-holdout.mjs`) whose console output never prints the actual values &mdash; only a row count and
the seed. The rendered image was viewed and transcribed **first**; `ground-truth.json` was opened
only afterward, to compare. Result: **10/10 exact match**, genuinely cold.

## Reproduce it

```bash
node gen-holdout.mjs                    # regenerates ground-truth.json + holdout-text.txt (same seed, byte-identical)
node count-tokens.mjs <path-to.json>    # real Anthropic token count for a content-blocks JSON file (needs your own credential)
```

Serve `render-harness.html` and call `window.__render(text, {fontPx, maxWidthPx})` in the browser to
get `{width, height, dataUrl}` &mdash; wrap the `dataUrl`'s base64 payload in an image content block
and pass it to `count-tokens.mjs` for the real image-token count. Full step-by-step is in
[findings.json](findings.json)'s own `reproduce` field.

## Gate

```bash
node --test kernel.test.mjs
```

18 tests. The two pure functions behind the renderer &mdash; `tokensForImage` (Anthropic's documented
formula, pinned against a real-world example: Anthropic's own 1092&times;1092 max-recommended-edge
figure) and `layoutPixels` (the character-wrapping math) &mdash; are gated. The empirical parts (the
real API calls, the vision read) are **not** gated, and this repo doesn't pretend otherwise; they're
documented honestly in `findings.json` instead.

```bash
node tools/witness.mjs mutate kernel.mjs --timeout 15000 --cap 400 --test node --test kernel.test.mjs
```

**23/23 mutants killed. Zero baselined survivors.** CI re-proves the mutation gate and the page
fixpoint (the live page's inlined kernel *and* findings both match their source files exactly) on
every push.
